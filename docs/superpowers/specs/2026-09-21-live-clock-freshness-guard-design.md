# G2 持续 PTP 映射与观测新鲜度门控设计

日期：2026-09-21

## 目标与边界

建立独立、持续更新、失效关闭（fail closed）的 PTP 时间映射服务，并让
`MotionBackend` 在每次普通观测和动作后继观测进入 Gym 之前验证源数据的新鲜度。
门控发现映射过期、时钟异常、相机过旧或错位、关节/TF 冻结或动作后观测时序
不确定时，必须拒绝观测并触发现有停止和锁止路径。

本设计不校准或修改系统时钟、PHC，不调用 `phc2sys`，不发送机器人、夹爪或
控制模式指令。时间健康只能作为动作许可的必要条件，绝不设置或提升
`allow_motion`。操作员报告硬件急停现已可用，但尚未完成受控停机验收；此次实现
和现场验收仍保持 `allow_motion=False`，不能据此启动机器人运动或训练。

## 架构与权限

系统分为三个互相独立的边界：

1. `g2_local.clock_monitor` 是操作员显式启动的前台监控服务。Python 服务以普通
   用户运行，只启动一条固定模板的特权 PTP 测量命令。
2. PTP 子进程固定使用 `enp3s0`、IEEE 802.3、E2E、软件时间戳、client-only 和
   `free_running=1`。命令禁止 `phc2sys` 和任何时钟调整路径，并由明确的最长运行
   时间包裹，防止特权进程无限残留。
3. Actor/Gym 只通过当前用户可访问的 Unix socket 读取不可变快照。Actor 不能
   启动、停止、重配或重启 PTP，不能通过该 socket 请求任何状态改变。

操作员先执行 `sudo -v`，随后启动监控服务。Actor 不调用 sudo。PTP 的第二个
管理 socket 仅接受 GET，使用会话唯一地址；监控服务自己的 socket 位于显式
runtime 目录，父目录与 socket 仅当前用户可访问。服务拒绝已有输出目录、已有
socket、同路径重复实例和不匹配的所有者/权限。

服务只管理自己创建且 PID 已知的子进程和进程组，不使用 `pkill`。正常退出先发布
不健康快照，再终止自己的子进程。异常退出即使无法发布，客户端短租约也会过期。
外层固定最长运行时间是特权进程最终回收边界；超时后服务退出，不能自动续期。

## 持续映射

监控器逐行解析 `ptp4l` 输出，并定期通过只读管理 socket 查询
`TIME_PROPERTIES_DATA_SET`。它保留有限滑动窗口，至少包含 8 个有效偏差样本且
覆盖不少于 10 秒；每个新样本到来后重新拟合，而不是从传感器年龄反推偏差。

当前现场已唯一确认 GDK 使用 `raw_ptp` 尺度。linuxptp 软件时间戳模式报告的偏差
包含 37 秒 UTC correction，映射到 GDK 源时间时明确减去该 correction。服务仍在
每次运行中复核主时钟 ID、`ptpTimescale=1`、`currentUtcOffset=37` 和无闰秒公告。
`currentUtcOffsetValid=0` 会保留在快照中，表示使用显式 37 秒 fallback；它不证明
UTC 可追溯性，也不证明每个传感器物理时钟身份。

以下任一条件令监控器立即进入不健康状态：

- 未完成窗口预热、PTP 主时钟不是显式期望值或运行中改变；
- 偏差样本缺失、重复、倒退，相邻间隔超过 4 秒或日志到达异常迟延；
- 漂移超过 100 ppm、拟合最大残差超过 1 ms；
- 路径延迟为负或超过 1 ms；
- UTC/PTP 属性缺失、查询失败、发生改变或宣布闰秒；
- 本机 wall 与 monotonic 的关系发生超过 1 ms 的跳变；
- PTP 子进程退出、输出损坏、socket 失效或内部异常。

这些是时钟映射健康界限，不是插入任务的观测阈值。每份健康映射租约截止最后
有效 PTP 样本后 2.5 秒；服务不能通过重复发送旧快照延长租约。

## 快照协议

Unix socket 使用有长度上限的单行 JSON 请求/响应协议。客户端只发送固定
`{"op":"snapshot","schema":1}`；服务拒绝其他操作、附加字段、超长或非 UTF-8
消息。响应字段固定为：

- `schema`、`sequence`、`healthy`、`reason`；
- 本机 `boot_id`、监控 `session_id`、期望和实际 PTP master；
- 时间尺度和 UTC correction/valid/leap 属性；
- 映射参考 monotonic 时刻、该时刻偏差、漂移、残差、路径延迟和经验误差；
- 快照创建 monotonic 时刻、最后 PTP 样本 monotonic 时刻和 `valid_until_ns`。

所有数字必须有限且处于验证范围。客户端核对 schema、当前 boot ID、固定 master、
时间尺度、严格递增 sequence、租约以及本机接收 monotonic 时刻。服务断开、响应
超时、格式错误、序号倒退或不健康响应均视为门控失败。客户端不从磁盘加载旧
快照，也不在失败后自动恢复当前 `MotionBackend`。

## GDK 观测证据

`GdkReader.observe()` 保持策略 observation 不变：7 维 XYZ+xyzw 状态和两路 RGB。
它在 `last_info` 中额外提供：

- 左右相机源时间戳；
- 关节状态时间戳；
- `lookup_transform_latest` 两种参数方向的源时间戳和位姿；
- 与 motion 状态左末端位姿一致的 TF 时间戳；
- TF/motion 位置与旋转差；
- 本次读取开始/结束的 wall、monotonic 与 GDK Clock 时间。

初始化时在读取循环开始前有界等待两个 TF 查询方向均可用。运行期任一 GDK/TF
调用失败就拒绝当前观测；不能用之前的值填补。motion 状态没有自身源时间戳，
因此其位姿只接受 TF 的交叉一致性检查，不宣称拥有独立的新鲜度证明。

## 新鲜度门控

`ObservationFreshnessGuard` 是有状态、线程安全的可调用对象，供
`MotionBackend` 现有 `observation_guard(obs, info, after)` 接口使用。构造时必须
显式提供全部任务阈值；生产路径没有隐式默认值。未配置、非有限、非正数或互相
矛盾的阈值直接拒绝构造。

首轮现场数据只给出候选起点：相机年龄 100 ms、关节/TF 年龄 50 ms、双相机
源时间戳差 50 ms、TF/motion 位置差 5 mm、旋转差 0.02 rad、映射经验误差
5 ms。这些数值不写成生产默认值，不代表允许观测产生相应物理误差；必须在双
相机、GDK 和真实 Actor 推理同时运行的只读负载测试后显式批准。

门控将源时间戳通过映射换算为本机 monotonic 采集时刻区间。经验误差作用于区间，
不修改策略 observation：

- 普通观测要求最坏情况下的年龄仍不超过对应显式阈值；
- 任一源最早可能采集时刻在未来，则拒绝；
- 两相机源时间戳差不得超过显式阈值；
- 每个源时间戳必须相对上一份已接受观测严格递增；冻结或倒退立即拒绝；
- TF/motion 位姿差不得超过显式位置和旋转阈值；
- 映射经验误差不得超过显式上限；
- 当 `after` 是命令首次确认发送的本机 monotonic 时刻时，左右相机、关节和 TF
  的最早可能采集时刻都必须严格晚于 `after`。误差区间跨过动作时刻就拒绝，
  不猜测事件顺序。

状态只在整份观测全部通过后提交，失败观测不能推进“上一时间戳”，避免失败数据
掩盖后续冻结。门控失败给出稳定的机器可读原因和人类可读诊断，但上层只依赖
布尔拒绝/异常契约。

## MotionBackend 与 Gym 行为

`MotionBackend` 保留现有顺序：读取 → 校验 observation → 规划 → 提交命令；
因此动作前门控失败时没有任何命令进入发送流。动作后门控失败走现有 `_abort()`，
停止流并永久锁止本实例。映射之后恢复健康也不会恢复当前回合或后台实例，必须
由操作员检查原因并显式重建。

门控本身不能设置 `allow_motion`、不能构造 GDK command port、不能改变控制模式、
不能发送保持命令。时间监控健康、观测健康、`allow_motion` 和现场安全许可是相互
独立的必要条件。此次交付保持真实 `allow_motion=False`。

## 故障与日志

监控器以追加写 JSONL 保存 PTP 原始行、属性查询、拟合更新、状态转换和退出原因；
每次运行使用新目录且不覆盖历史证据。高频健康快照不逐条落盘，只记录映射更新和
健康状态变化，避免无界日志增长。文件写入失败令服务不健康并退出。

客户端记录拒绝类别但不记录图像内容。重复相同故障进行限频，首次故障必须保留。
socket 阻塞有短超时，Gym 线程不会无限等待监控器。监控客户端关闭不会停止服务，
服务关闭也不会调用机器人接口。

## 测试与验收

实现遵循测试先行：

1. 映射窗口测试覆盖预热、持续更新、租约过期、漂移/残差/路径延迟、主时钟变化、
   UTC 属性、wall 跳变、损坏和迟到日志。
2. socket 协议测试覆盖权限、唯一实例、消息上限、错误 schema/操作、超时、断连、
   boot/session/sequence 校验和旧快照不可续租。
3. 观测门控测试覆盖每个源的年龄上下界、误差区间、相机时差、冻结/倒退、未来
   时间、TF/motion 差和失败状态不提交。
4. MotionBackend 测试证明动作前失败零发送，动作后失败调用停止并锁止，映射恢复
   不自动恢复实例。
5. 子进程生命周期测试证明命令模板不含校时路径、只清理自有 PID/进程组、最长
   运行时间生效、异常退出令租约自然过期。
6. 运行完整软件测试套件，并检查代码差异。
7. 现场仅以 `allow_motion=False` 运行持续监控、双相机/GDK和模拟 Actor 推理负载，
   输出延迟分布与候选阈值报告。没有阈值批准和单独的硬件急停/停止距离验收，
   不进行真实 Gym step 或训练。

## 交付范围

本阶段交付监控服务、只读客户端、GDK 时间证据扩展、观测门控、MotionBackend
接线接口、测试、启动/停止说明和只读负载测量入口。它不交付最终任务阈值、真实
运动授权、奖励/成功判定、碰撞/速度/姿态包络或正式真机训练启动。
