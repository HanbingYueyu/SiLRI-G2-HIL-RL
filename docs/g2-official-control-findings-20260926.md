# 官方 GDK 文档核对（2026-09-26）

## 已确认与本次修复

官方站点当前提供 4.1.5 文档。以下结论针对该版公开说明，不能替代本机固件实测。

- [开发规范](https://support.agibot.com/?gdk_version=4.1.5#contents/reference/guidelines.md)：模块对象非线程安全，同一对象多线程调用须加锁。本项目观测线程和发送线程共享 Robot，但原先各自持有不同锁，存在并发调用路径。
- 已在 `GdkReader` 构造共享的串行 Robot 代理；相机读取不持有 Robot 锁。发送线程拿到 Robot 锁后执行健康、新鲜度和取消检查，再发送；停止读取不跨整个流程持有 Robot 锁，避免与 reader_lock 形成锁序环。
- 两项关键覆盖：读状态与发送不能同时进入 SDK；等待 Robot 锁时收到取消不得补发。相关 reader/command-port 离线检查 106 项通过，耗时约 0.3 秒；未执行真机运动。不能据此认定相机/PTP 间歇问题已根治。

## 不能从文档推导的保证

**实现进展（2026-09-27）：** 已在 `libgdk_core.so.4.1.5` 确认完整模式接口实现并补扩展绑定；保持失败时请求左臂 SAFE_STOP，不读取失效映射。编译、ABI 注册/字段和离线故障路径通过，未向机器人调用。请求应答与物理停止分开；同一对象仍串行，不能保证通信断开/SDK 阻塞时有效。详见 `g2-training-handoff-20260927.md`。

**2026-09-27 补充纠正：不能把 Python 未暴露等同于 GDK 没有停止请求。** 本机 4.1.5（071be97）的 `include/gdk/robot.h:127` 声明 `SetControlModeFull`；`include/common/types.h:902` 的完整参数中，`Target::TARGET_LEFT_ARM=1`、`SafeMode::SAFE_STOP=2`（注释“安全停”）。`libgdk_adapter.so.4.1.5` 确实导出该方法。安装的 Python `Robot` 类及 `bind_robot.cpp` 只暴露 `set_control_mode`，没有完整模式接口。这是可继续实现绑定的明确线索，尚不能证明固件停止延迟、夹持保持或现场验收。检查仅导入模块枚举类成员，未实例化 Robot、未调用控制接口。

- [Robot 接口](https://support.agibot.com/?gdk_version=4.1.5#contents/reference/Python/robot.md) 的 `end_effector_pose_control` 要求 50 Hz、连续目标、小范围运动，且明确注明该接口无碰撞检测。不能把机器人其他模式的碰撞检测当作此接口的安全保证。
- 同页 `life_time` 只标为生命周期，未明确到期制动时延、距离及独立停止接口；`mode=0` 是状态，不是可传入 `set_control_mode` 的停止值，后者仅支持 1/2/3。
- `get_whole_body_status` 的急停字段是状态读取，不是软件急停请求接口。

## 阈值结论

- [PTP 指南](https://support.agibot.com/?gdk_version=4.1.5#contents/howto/ptp.md) 提到软件同步后的误差和漂移；这不等于允许旧图像、失效映射继续控制。官方校时脚本会涉及实际时钟同步，本次未运行。
- 本项目约 2 秒一个偏差报告，映射租约 2.5 秒，隔离一次异常样本可能导致过期。可研究延长租约，但必须结合现有证据重放及随外推时间增长的误差核验，不能仅凭“到期报错”增加数字。
- 后续已将映射租约有限调整至 4.5 秒，其他阈值和停止校验未放宽，依据如下。映射失效时停止保持无法确认的问题仍未解决。

## 历史重放与修复

输入：`/tmp/g2-demo-*/evidence.jsonl` 共 54 份，1390 个相邻报告间隔为 1.997～2.003 秒。按原事件顺序重放 `ClockWindow` 的 PTP、时间属性和快照事件；仅在离线进程内切换候选租约，不连接硬件。

发现并修复：剔除异常拟合样本后，已接受样本间隔超过 4 秒会触发永久 `mapping_invalid`，即使原始 PTP 报告持续正常到达。现在区分这两种间隔：原始报告断流仍拒绝；拟合窗口缺口则撤销映射、重新收集完整预热窗口，期间不授权动作。

修复后同一批历史快照对比：

| 租约 | 正常快照 | 过期快照 | 预热快照 | 最大经验误差 |
| --- | ---: | ---: | ---: | ---: |
| 2.5 秒 | 932 | 18 | 63 | 3.663 ms |
| 4.5 秒 | 956 | 0 | 57 | 4.063 ms |

两者均保留 1 个 PTP 故障、2 个原始报告间隔故障快照。延长期内有 15 个下一报告可对照，外推与该报告偏差最大 1.092 ms。以上是已记录快照计数，不是在线故障率；部分日志在故障后结束，缺少后续数据，不能证明长期稳定或物理安全。

采用 4.5 秒租约，允许约一次 2 秒报告异常加调度余量；仍按 100 ppm 累加外推误差、执行 5 ms 误差上限，并拒绝主时钟变化/原始断流/过期等。异常样本和重复读取均不能续租。相关离线检查 402 项通过（约 2.2 秒）。

运行中的旧监控不会热更新，必须在所有采集/运动进程结束后换用新监控。核对时未发现这些进程运行，本次未启动或终止硬件进程。旧版审计/代码身份不能冒充新版现场验收。
